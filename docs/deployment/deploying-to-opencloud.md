# Deploying to OpenCloud v8

How a built extension gets into an OpenCloud server. Verified in rework step 2 against the
production compose stack on rolling 8.0.1 (local setup:
[local-dev-environment](local-dev-environment.md)). The old Docker/nginx/`install.sh` deployment
was removed in step 1.

## Build output

`pnpm build` writes `dist/`:

- `manifest.json` — generated by `@opencloud-eu/extension-sdk`: `name`, `version`, `description`,
  `license`, `author` copied from `package.json`, plus `entrypoint` (e.g.
  `js/remoteEntry-<hash>.mjs`), merged with `src/manifest.json` (the `config` block with the limit
  defaults).
- `js/*.mjs` — Module Federation remote entry and chunks; shared host modules (`vue`,
  `vue3-gettext`, `@opencloud-eu/web-pkg`, …) are **not** bundled. Each file carries a
  `/*! archive-viewer v<version> */` comment, so a deployed build shows its version.

`pnpm package` packs `dist/` into `release/archive-viewer-<version>.zip` (+ `.sha256`) whose
top folder is already `archive-viewer/` and which also carries `LICENSE` and
`THIRD-PARTY-NOTICES.md` (see [build-tooling](../tech-stack/build-tooling.md)).

## Installing

From a release zip: check it (`sha256sum -c archive-viewer-<version>.zip.sha256`) and unzip it in
the apps directory below, which creates `archive-viewer/`; then restart (step 2). By hand:

1. Put the contents of `dist/` in a folder named **`archive-viewer`** (the folder name becomes the
   app id) inside the server's web apps directory:
   - **opencloud-compose** (the main server's setup): `config/opencloud/apps/archive-viewer/`,
     or wherever `OC_APPS_DIR` in `.env` points. It's mounted at
     `/var/lib/opencloud/web/assets/apps` in the container.
   - Plain install: `$OC_BASE_DATA_PATH/web/assets/apps` by default, changed with
     `WEB_ASSET_APPS_PATH`.
2. Restart OpenCloud (`docker compose restart opencloud`). New apps and `apps.yaml` changes are
   only read at startup.

Requirements from the OpenCloud web service: each app has its own directory, contains a
`manifest.json` with `entrypoint`, and may contain a `config.json`.

## How to check it's installed

- `https://<server>/config.json` → `external_apps` lists
  `{ "id": "archive-viewer", "path": "/assets/apps/archive-viewer/js/remoteEntry-<hash>.mjs", "version": "…" }`.
- Files are served under `https://<server>/assets/apps/archive-viewer/`.
- In Files, right-click a `.zip` → "Open in Archive Viewer".

## Configuring

`apps.yaml` (opencloud-compose: `config/opencloud/apps.yaml`, mounted to `/etc/opencloud/apps.yaml`),
keyed by app id:

```yaml
archive-viewer:
  config: # all optional; sizes in bytes, defaults shown
    maxArchiveSize: 1073741824 # 1 GiB: largest non-ZIP archive downloaded in full
    maxUncompressedSize: 2147483648 # 2 GiB: largest decompressed output (gz/bz2/xz/lzma)
    maxEntrySize: 1073741824 # 1 GiB: largest extracted file or selection
    maxArchiveSizeMobile: 268435456 # 256 MiB (phones and tablets)
    maxUncompressedSizeMobile: 536870912 # 512 MiB
    maxEntrySizeMobile: 268435456 # 256 MiB
```

Values are merged with the manifest's `config` and reach the component as the
`applicationConfig` prop. ZIPs are read by HTTP Range requests and have no archive size limit
([zip-range-reading](../source/zip-range-reading.md)); a reverse proxy in front of OpenCloud must
pass `Range` through (Traefik in opencloud-compose does). `disabled: true` (in `apps.yaml` or the app's `config.json`) stops the
app from loading.

## Releasing (not done yet)

1. Bump `version` in `package.json` (semver; the manifest and JS banner copy it) and date the
   version's entry in `CHANGELOG.md`.
2. `pnpm install --frozen-lockfile`, all checks, `pnpm build`, `pnpm package`.
3. Test the zip on a server (unzip, restart, `/config.json` check).
4. Merge to `main`, tag `v<version>`, create a GitHub release and attach the zip and `.sha256`.

Version 0.1.1 is prepared but no tag or release exists yet.

## Production security policy (CSP)

opencloud-compose serves the CSP from `config/opencloud/csp.yaml`. Observed on 8.0.1:
`worker-src 'self' blob:` (web workers allowed) but `script-src` without `'wasm-unsafe-eval'`, so
**WebAssembly is blocked**. A WASM-based archive engine would need the server's `csp.yaml`
changed; a pure-JS engine works as is. See
[opencloud-v8-compatibility](../architecture/opencloud-v8-compatibility.md).

## Version alignment

The app's `@opencloud-eu/*` packages are pinned to the server's line (`~8.0.0` for an 8.0.x
server); see [dependencies](../tech-stack/dependencies.md).
