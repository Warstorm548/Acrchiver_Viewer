# Security Notes

Archive contents (file names, data) are **untrusted input**: anyone who can put an archive in
a user's storage, or share one by public link, controls them. Review every place entry names or
contents reach the DOM, memory or storage.

## How the viewer handles untrusted archives (step 3)

| Rule              | Implementation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No HTML injection | Names, paths and text previews render only via `v-text`, `{{ }}` and bound attributes; no `v-html`/`innerHTML` anywhere. Test fixture `x" onmouseover="alert(1)".txt` checks this in the browser. (The removed legacy app had a real XSS here.)                                                                                                                                                                                                                                                                                                                                                                |
| SVG / images      | Shown only as `<img :src="blob:…">` (scripts in SVG don't run in `<img>`); blobs get an explicit MIME type from the extension; object URLs revoked on close.                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Archive size      | `maxArchiveSize` (1 GiB desktop / 128 MiB mobile) checked against `resource.size` **before** a full download, and against the bytes actually received **during** it (the metadata can be wrong). ZIPs are read by range and never held whole in memory.                                                                                                                                                                                                                                                                                                                                                        |
| Zip bombs         | gzip, bzip2, xz and lzma decompression aborts above `maxUncompressedSize` (2 GiB / 384 MiB; never more than `MAX_BUFFER_SIZE`, 2 GiB − 16 MiB). A size recorded in the archive only sizes the first buffer (gzip's is ignored beyond deflate's ~1032:1 ratio). Every extracted file, and the total of a selection, is capped at `maxEntrySize` (1 GiB / 256 MiB); for ZIP the cap counts the **real** output bytes — for a selection, the real total across all files (each read gets what is left) — and zip.js stops at the declared size anyway. Previews only for entries ≤ 10 MiB, at most 1 MiB of text. |
| Download names    | `sanitizeFileName` replaces `/`, `\` and control characters before `a.download`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Path traversal    | Nothing is written to disk or to OpenCloud; `..` stays display text. The selection zip drops `.`/`..` segments and control characters from entry paths (`selectionPath`), so extracting it can't escape its folder ("zip slip"). Mandatory to handle again if "extract to folder" is ever added ([roadmap-considerations](../overview/roadmap-considerations.md)).                                                                                                                                                                                                                                             |
| Duplicate paths   | A repeated path shows its last occurrence, the same data preview/download return, so an archive can't list one file and deliver another.                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Auth              | The archive is fetched only from the pre-signed `url` OpenCloud's `AppWrapperRoute` provides (renewed via the wrapper's `getUrlForResource` when it expires). The only token the app handles is the login token sent to the server helper, and only to a same-origin path (`resolveHelperUrl` refuses absolute and `//` URLs).                                                                                                                                                                                                                                                                                 |
| CSP               | No WebAssembly (zip.js native build, own bzip2/xz/lzma decoders), so `script-src` needs nothing extra. Workers only from `blob:` (zip.js and the decompression worker), allowed by opencloud-compose's `worker-src 'self' blob:`. OpenCloud's **built-in** CSP (no `csp.yaml`) blocks them; zip.js and the decompressor then run on the main thread (works, but the page freezes while bzip2/xz/lzma decode).                                                                                                                                                                                                  |

## Hosting headers

The app is served by OpenCloud itself, which sets its CSP (`PROXY_CSP_CONFIG_FILE_LOCATION`;
opencloud-compose `config/opencloud/csp.yaml`). No CSP change is needed (adding `worker-src 'self'
blob:` to a built-in-CSP install keeps decoding off the main thread); the risks of
allowing WebAssembly are recorded in [roadmap-considerations](../overview/roadmap-considerations.md).

## Server helper (0.3.0, ZIP and 7z in 0.4.0)

The optional helper ([overview](../source/archive-helper/overview.md)) parses untrusted archives
**on the server**, so it follows the same rules plus these:

| Rule                | Implementation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Who may open what   | Login required by the proxy, which overwrites `X-Remote-User`; the file is fetched over WebDAV with the user's own token, so OpenCloud's permissions apply; WebDAV paths must start with `/spaces/` and contain no `.`/`..`/empty/control segments.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Sessions            | 256-bit random IDs; every call checks the owner; another user's session answers "not found".                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Downloads           | The unprotected download route trusts only a single-use, 60 s ticket and ignores `X-Remote-User` (the proxy passes a client's value through there).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Resource exhaustion | Storage reservations before copying (total, per user, real free space) with a hard stop; entry, decompressed-size, name and time limits while listing; LZMA/LZMA2 dictionaries, PPMd memory and zstd windows checked (≤ 256 MiB) before allocating; download caps and per-user concurrency; container memory/CPU limits. See [storage-limits](../source/archive-helper/storage-limits.md).                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Parser              | Go (memory-safe); tar from the standard library; own xz container code tested against the reference `xz`, including damaged input. ZIP: own central-directory parser that refuses a declared count over `MaxEntries` before reading headers. 7z: `bodgit/sevenzip` audited 2026-10-28: header counts were bounded only at 2³² before `make()` (a few bytes could declare 4 billion files and crash the helper), so a patched copy caps them at `MaxEntries`, the header at 512 MiB, folders at 64 coders/streams and all coders at 4 × `MaxEntries`, and checks stream indexes (`server/third_party/sevenzip/PATCHES.md`); library panics are recovered as `corrupt`; its memory-heavy decoders are replaced by ones that check first; encrypted 7z/ZIP data is never decrypted ([zip-and-7z](../source/archive-helper/zip-and-7z.md)). |
| Temp files          | One copy per open archive, random name `ah-<id>`, mode 0600, owned by the helper's own user (1500:1500 by default); entries are never written to disk; startup cleanup deletes only `ah-*` files.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Download names      | `Content-Disposition` with a sanitized ASCII fallback and `filename*`; ZIP paths without `.`/`..` (port of `selectionPath`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Container           | Read-only root, all capabilities dropped, `no-new-privileges`, no published port and no `EXPOSE` (reachable only through the proxy, port from `.env`; a loopback listen address logs a warning). Tokens and file names are not logged.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
