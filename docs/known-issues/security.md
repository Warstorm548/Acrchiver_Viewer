# Security Notes

Archive contents (file names, data) are **untrusted input**: anyone who can put an archive in
a user's storage, or share one by public link, controls them. Review every place entry names or
contents reach the DOM, memory or storage.

## How the viewer handles untrusted archives (step 3)

| Rule              | Implementation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No HTML injection | Names, paths and text previews render only via `v-text`, `{{ }}` and bound attributes; no `v-html`/`innerHTML` anywhere. Test fixture `x" onmouseover="alert(1)".txt` checks this in the browser. (The removed legacy app had a real XSS here.)                                                                                                                                                                                                                                                                              |
| SVG / images      | Shown only as `<img :src="blob:…">` (scripts in SVG don't run in `<img>`); blobs get an explicit MIME type from the extension; object URLs revoked on close.                                                                                                                                                                                                                                                                                                                                                                 |
| Archive size      | `maxArchiveSize` (1 GiB desktop / 128 MiB mobile) checked against `resource.size` **before** a full download, and against the bytes actually received **during** it (the metadata can be wrong). ZIPs are read by range and never held whole in memory.                                                                                                                                                                                                                                                                      |
| Zip bombs         | gzip, bzip2, xz and lzma decompression aborts above `maxUncompressedSize` (2 GiB / 384 MiB; never more than `MAX_BUFFER_SIZE`, 2 GiB − 16 MiB). A size recorded in the archive only sizes the first buffer (gzip's is ignored beyond deflate's ~1032:1 ratio). Every extracted file, and the total of a selection, is capped at `maxEntrySize` (1 GiB / 256 MiB); for ZIP the cap counts the **real** output bytes, and zip.js stops at the declared size anyway. Previews only for entries ≤ 10 MiB, at most 1 MiB of text. |
| Download names    | `sanitizeFileName` replaces `/`, `\` and control characters before `a.download`.                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Path traversal    | Nothing is written to disk or to OpenCloud; `..` stays display text. The selection zip drops `.`/`..` segments and control characters from entry paths (`selectionPath`), so extracting it can't escape its folder ("zip slip"). Mandatory to handle again if "extract to folder" is ever added ([roadmap-considerations](../overview/roadmap-considerations.md)).                                                                                                                                                           |
| Duplicate paths   | A repeated path shows its last occurrence, the same data preview/download return, so an archive can't list one file and deliver another.                                                                                                                                                                                                                                                                                                                                                                                     |
| Auth              | The archive is fetched only from the pre-signed `url` OpenCloud's `AppWrapperRoute` provides (renewed via the wrapper's `getUrlForResource` when it expires); no tokens handled by the app.                                                                                                                                                                                                                                                                                                                                  |
| CSP               | No WebAssembly (zip.js native build, own bzip2/xz/lzma decoders), so `script-src` needs nothing extra. Workers only from `blob:` (zip.js and the decompression worker), allowed by opencloud-compose's `worker-src 'self' blob:`. OpenCloud's **built-in** CSP (no `csp.yaml`) blocks them; zip.js and the decompressor then run on the main thread (works, but the page freezes while bzip2/xz/lzma decode).                                                                                                                |

## Hosting headers

The app is served by OpenCloud itself, which sets its CSP (`PROXY_CSP_CONFIG_FILE_LOCATION`;
opencloud-compose `config/opencloud/csp.yaml`). No CSP change is needed (adding `worker-src 'self'
blob:` to a built-in-CSP install keeps decoding off the main thread); the risks of
allowing WebAssembly are recorded in [roadmap-considerations](../overview/roadmap-considerations.md).
